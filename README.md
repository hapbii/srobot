# SCARA 제어 프로그램 V2

웹 3D 시뮬레이터, 블록 편집기, 라즈베리파이 통합 HTTP/WebSocket 서버, Arduino Nano 3축 펌웨어입니다.

라즈베리파이가 프런트엔드와 백엔드를 함께 제공합니다. 부팅 자동 실행·종료·브라우저 자동 실행은 [배포 안내](deploy/README.md)를 참고하세요. 실제 Pi에 배포하고 검증한 결과와 하드웨어 미확인 사항은 [실물 환경 검증 기록](deploy/VALIDATION.md)에 정리합니다.

## 다른 컴퓨터로 전체 파일 옮기기

기준 저장소는 **[hapbii/srobot](https://github.com/hapbii/srobot)**이며 비공개입니다. 2026-11-12에 최신 작업 코드, 웹 화면, 3축 펌웨어, 배포 설정, 테스트, 문서와 백업 ZIP 6개를 모두 포함했습니다. 이동할 때도 이 저장소를 사용하세요. 별도로 만든 `srobot-full-20261112`는 당시 전체 파일을 담은 사본입니다.

### ZIP으로 받기

1. 저장소 접근 권한이 있는 GitHub 계정으로 로그인합니다.
2. [srobot 저장소](https://github.com/hapbii/srobot)의 `main` 브랜치에서 **Code → Download ZIP**을 선택합니다.
3. 옮길 컴퓨터에서 압축을 풉니다. `README.md`, `scara_main.py`, `index.html`이 있는 폴더가 프로젝트 루트입니다. 기존 PC의 `D08290555` 폴더에 있던 코드가 이 위치에 있습니다.

ZIP에는 현재 파일이 들어 있습니다. 커밋 이력과 이후 업데이트도 함께 관리하려면 Git으로 받습니다.

### Git으로 받기

Git을 설치하고 저장소 접근 권한이 있는 계정으로 인증한 뒤 실행합니다.

```sh
git clone https://github.com/hapbii/srobot.git
cd srobot
```

이후 최신 변경은 프로젝트 폴더에서 `git pull --ff-only`로 받습니다. 로컬에서 수정한 파일이 있다면 먼저 커밋하거나 별도로 보관합니다.

최신 실행 코드는 저장소 루트와 각 코드 폴더에 있고, `backups/`는 이전 시점의 사본입니다.

| 백업 파일 | 내용 |
|---|---|
| `backups/D11091222.zip` | 최초 리팩터링 전 원본 |
| `backups/D11091250.zip` | 불필요한 파일 정리 전 사본 |
| `backups/D11091307.zip` | Pi 통합 웹 서버·자동 실행 변경 전 사본 |
| `backups/D11091342.zip` | 최초 Pi 배포 소스와 세 보드의 기존 flash 읽기 백업 |
| `backups/D11091351.zip` | PC의 USB 종료 경합 수정 전 소스 |
| `backups/D11091353.zip` | Pi의 USB 종료 경합 수정 전 배포 소스 |

백업 이름은 한국 시간 기준 `DMMddHHmm.zip` 형식입니다. 예를 들어 `D11091342.zip`은 11월 9일 13시 42분의 백업입니다. 이번 전체 파일 이전 요청에 따라 기존 백업 6개를 저장소에도 포함했습니다. 이후 새 백업은 [작업 규칙](AGENTS.md)에 따라 별도로 보관합니다.

파일을 받은 뒤 Python 가상 환경과 의존성은 옮긴 컴퓨터에서 새로 설치합니다. 화면만 확인하려면 아래의 `--demo` 실행 방법을, 새 라즈베리파이에 설치하려면 [배포 안내](deploy/README.md)를 따르세요. 파일 다운로드만으로 새 장치에 부팅 자동 실행 서비스가 설치되지는 않습니다. 기존 보드에는 V2 펌웨어가 업로드된 상태이며, 파일을 옮겼다는 이유만으로 다시 업로드할 필요는 없습니다.

마지막 실물 확인일은 2026-11-09입니다. 웹 서버·종료·부팅 자동 실행은 확인했지만, 이후 아두이노 3대가 전원 꺼짐·USB 미인식 상태여서 복구 확인이 남았습니다. 실제 모터 회전·엔코더·원점 센서 검증도 남아 있었습니다. 상세 내용은 [실물 환경 검증 기록](deploy/VALIDATION.md)을 참고하세요.

## 업데이트와 실행

**웹 파일, Python 파일, J1/J2/J3 펌웨어를 함께 업데이트해야 합니다.**
서버는 `J1 READY V2` 등으로 식별되는 보드만 연결합니다. 이전 펌웨어의 수신 확인만으로 도착을 판단하지 않습니다.

1. Arduino IDE에 AccelStepper 라이브러리를 설치합니다. 검증에 사용한 버전은 1.64입니다.
2. J1 보드에 `J1/J1.ino`, J2에 `J2/J2.ino`, J3에 `J3/J3.ino`를 각각 업로드합니다. 각 폴더의 `axis_firmware.h`도 함께 필요합니다.
3. 라즈베리파이에 Python 3.10 이상으로 다음을 실행합니다.

   ```sh
   python3 -m venv .venv
   . .venv/bin/activate
   pip install -r requirements.txt
   python scara_main.py
   ```

   자동 식별 대신 `python scara_main.py --j1 /dev/ttyUSB0`처럼 일부 포트를 지정할 수 있습니다. 나머지는 READY V2로 식별하며 포트 번호로 축을 추측하지 않습니다.

4. 브라우저에서 `http://라즈베리파이IP:8080`을 엽니다. Pi 자체에서는 `http://localhost:8080`을 엽니다. 화면 파일 다운로드와 `/ws` 제어 연결이 자동으로 처리되므로 별도 HTTP 서버나 IP 입력이 필요하지 않습니다.
5. `제어 시작`을 눌러야 수동/추적 변경을 실제 장치로 보냅니다. 블록/웨이포인트 실행은 명시적인 이동 시작 동작으로 처리합니다. 부팅이나 웹 접속만으로 모터를 움직이지 않습니다.
6. `웹·제어 프로그램 종료` 버튼은 STOP → USB 정리 → 웹/제어 프로세스 종료를 수행합니다. 다시 사용하려면 서버를 시작합니다. Pi OS의 전원 종료는 별도로 수행합니다.

PC에서 USB 장치 없이 화면과 종료 흐름을 시험할 수 있습니다.

```sh
pip install -r requirements.txt
python scara_main.py --demo --host 127.0.0.1
# http://localhost:8080 접속. 종료 버튼을 누르면 Python 프로세스도 종료합니다.
```

Three.js r128은 `vendor/three.min.js`에 포함되어 인터넷 없이 로드됩니다. 원래 CDN 배포본의 MIT 라이선스 헤더를 유지했습니다. 서버 기본 주소는 `0.0.0.0:8080`이며 `--host`, `--port`로 변경할 수 있습니다. 동일한 신뢰 가능한 로컬 네트워크에서 사용합니다. 종료 API는 같은 출처의 요청과 해당 서버 세션의 토큰을 요구하며, `.py`/`.git`/설정 파일은 HTTP로 제공하지 않습니다. 인터넷 공개용 인증·TLS 프록시는 별도 구성입니다.

## 좌표와 배선

- 원점 센서 감지 자세는 **J1=0°, J2=180°, J3=0°**로 일관되게 정의했습니다. 기존 접힌 시작 자세를 유지한 설정입니다. 센서의 실제 기계 자세가 이 값에 대응하는지 실물에서 확인해야 합니다.
- 서버 `robot_config.py`: 전축 감속비 20:1, 드라이버 1600스텝/모터 1회전. 따라서 출력축 1°=88.8889스텝입니다.
- J1/J2 웹 범위 ±360°, J3 ±180°. 부팅 때 아두이노 위치 카운터는 0이며, 절대 위치를 복구하려면 HOME SET을 수행합니다. 다회전 위치와 홈은 재부팅 간 저장하지 않습니다.
- STEP=D9, DIR=D10, ENABLE=D11(active-low), 원점 센서=D13(INPUT_PULLUP, active-low).
- AS5600은 A4/A5의 두 배선 방향을 검사하는 소프트웨어 I2C를 사용합니다. 먼저 SCL=A4/SDA=A5를 시도합니다. 센서는 모터축에 장착된 기존 감속비 계산을 유지했습니다.
- HOME SET은 이미 눌린 센서에서 먼저 빠져나온 뒤 음의 방향으로 탐색합니다. 10ms 감지 확인, 거리 제한, 180초 제한을 적용했습니다.
- 서버/브라우저 통신과 서버/보드 통신에 각각 heartbeat가 있습니다. 2초 동안 통신이 없으면 정지합니다. 화면이 숨겨져도 정지하므로 브라우저 탭을 이동한 뒤에는 다시 시작해야 합니다.

HOME SET 후에도 J2 원점은 180°입니다. 원점 복귀와 블록 MoveHome도 같은 자세를 사용합니다.
정지는 목표와 속도를 현재 스텝 위치에 고정하고 드라이버를 비활성화하는 기존 방식입니다. 정지 후 같은 목표를 다시 보낼 수 있습니다.
USB가 늦게 부팅되거나 연결이 끊겼다가 돌아오면 미연결 포트를 3초 간격으로 재탐색합니다. 이미 연결된 포트는 다시 열지 않습니다. 재연결 과정에서 자동으로 운동을 재개하지 않으며 홈 상태를 다시 확인해야 합니다.

## 블록 실행

- MoveJ: 관절 공간 보간. degree 입력.
- MoveL: 손목각까지 반영한 정확한 FK/IK로 XZ 직선을 샘플링합니다. 전체 경로의 도달 범위를 먼저 검사합니다. X/Z는 화면 모델 단위이며 mm 보정값은 아닙니다.
- 화면의 보간이 끝나면 최종 목표를 명령 ID와 함께 전송합니다. 모든 축에서 동일 ID의 `STATE` 도착 응답을 받아야 다음 블록을 실행합니다. 응답이 없으면 시간 초과로 정지합니다.
- Loop/EndLoop로 반복 범위를 지정하며 중첩할 수 있습니다. 기존처럼 EndLoop 없는 Loop 하나를 쓰면 그 뒤 프로그램 전체를 반복합니다.
- If가 거짓이면 다음 블록 하나를 건너뜁니다. 다음이 Loop면 그 반복 범위 전체를 건너뜁니다.
- Stop/정지 버튼/편집기 종료는 화면 보간과 장치 운동을 함께 취소합니다.
- Gripper는 시뮬레이션 표시 기능입니다. 실물 그리퍼의 핀/드라이버 규약이 없으므로 HW 모드에서는 오류를 표시하고 정지합니다.
- 프로그램 JSON 내보내기는 블록과 변수를 포함합니다. 가져오기 UI는 기존과 같이 제공하지 않습니다.

STATE는 AccelStepper의 **스텝 카운터 도착 확인**입니다. 실제 축이 탈조 없이 도착했음을 엔코더로 보장하는 폐루프 제어는 아닙니다. 엔코더는 연속각/자석 상태 표시를 제공하며 실패·만료 값을 정상 측정으로 재사용하지 않습니다. 구동계 방향·감속비가 실물과 맞는지 검증 없이 PID 보정을 추가하지 않았습니다.

## 코드와 자원 소유권

| 파일 | 책임 |
|---|---|
| index.html | 기존 UI/3D 렌더링과 입력, 장면 수명 관리 |
| scara_core.js | FK/IK, 입력 검증, 반복문 실행기, 3D 자원 해제 도구 |
| hardware.js | 단일 50Hz 송신, 연결·재연결, 정지, 도착 Promise, 피드백 |
| block_editor.html / block_editor.js | 분리된 블록 편집기 |
| block_bridge.js | 팝업 소유 창 검증, 명령 전달, 종료 정리 |
| scara_main.py / web_app.py | HTTP·WebSocket 통합 실행, 설정/상태 API, 종료 수명 관리 |
| control_server.py | 단일 asyncio 스레드의 로봇 상태, 제어권, 홈, 도착, 오류 처리 |
| serial_transport.py | 제한된 버퍼, 포트 식별, 쓰기 실패, 수신 스레드 수명 |
| robot_config.py | 홈/감속비/범위/제한 상수 |
| firmware/axis_firmware.h | 3축 공통 펌웨어 원본 |
| firmware/sync_firmware.py | 각 Arduino 스케치 폴더에 공통 헤더 배포 |
| terminal_dashboard.py | 상태 데이터 보관 및 선택적 터미널 모니터 |
| deploy/ | Pi 서비스·설치·선택적 데스크톱 브라우저 실행 |
| tests/ | Python/Node 회귀 검사 및 브라우저 통합 검사 |
| vendor/ | 오프라인 화면 로드에 사용하는 Three.js |
| backups/ | 전체 파일 이전을 위해 포함한 과거 백업 ZIP 6개 |

공통 펌웨어를 수정했다면 `python firmware/sync_firmware.py` 실행 후 각 보드를 다시 빌드합니다.
현재 실행하지 않는 구형 BLE/DC/PWM/Pi 직접 I2C 구현과 과거 `.bak` 파일은 제거했습니다. 현재 V2 서버와 축별 스텝 펌웨어만 사용합니다. 정리 전 코드는 원래 프로젝트 폴더 밖에 보관했으며, 전체 파일 이전을 위해 해당 ZIP 사본을 저장소의 `backups/`에도 포함했습니다.

메모리 정리:

- 삭제한 웨이포인트는 전용 잔상 material만 dispose하고 공유 본체 geometry는 보존합니다.
- 캐리어는 전용 geometry/material을 정리합니다. 반복 생성 중에도 공유 재질은 유지합니다.
- 페이지 종료 시 RAF, 타이머, observer, 장면 이벤트 구독, 렌더 타깃/장면 자원, 팝업/소켓을 정리합니다.
- 서버의 serial inbox는 최대 256개입니다. 포화 시 정지합니다. 클라이언트 수/메시지 크기/전송 대기를 제한하며 수신 스레드를 종료 시 join합니다.
- 펌웨어는 동적 String 누적 대신 80바이트 고정 명령 버퍼를 사용합니다.

## 검증

```sh
python -m unittest discover -s tests -v
node --test tests/test_core.cjs
```

`tests/browser_smoke.py`는 Playwright와 Chrome이 설치된 Windows 환경에서 실행하는 WebGL/WebSocket 통합 검사입니다. 실제 serial 포트 대신 모의 모터를 사용합니다.

2026-11-09 검증: Python/Node 회귀 검사, 실제 Chromium의 화면·팝업·정지·모의 도착 대기 검사, Arduino Nano 3축 컴파일을 수행했습니다.
잔상 생성/삭제 15회 후 GPU geometry 117개/texture 1개가 유지됐습니다. 350ms 모의 모터 지연이 끝나기 전에 블록을 완료 처리하지 않는 것도 확인했습니다.
펌웨어는 축별 약 11.4KB flash, 전역 RAM 460바이트를 사용했습니다. 이후 실제 Pi에 배포하고 보드 flash 백업·V2 업로드·스텝 완료 응답·서버 종료·재부팅 자동 시작을 검증했습니다. 실제 모터 회전은 배선 문제로 확인하지 못했으며 상세 결과는 [실물 환경 검증 기록](deploy/VALIDATION.md)을 참고하세요.
