# 라즈베리파이 검증 기록 — 2026-11-09

## 환경과 배포

- 64비트 Debian 13 trixie / aarch64 / Python 3.13.5.
- 일반 사용자 권한의 `srobot.service`, `/opt/srobot`, HTTP/WebSocket 8080 포트.
- `dialout` 접근, 서비스 `enabled`, systemd unit 검사 통과.
- 데스크톱은 LightDM 자동 로그인 + Wayland/labwc, Chromium 설치 상태.
- J1=/dev/ttyUSB0(사용자 확인), J2=/dev/ttyUSB1(기존 READY 확인), J3=/dev/ttyUSB2.
- 세 FTDI 어댑터의 USB 시리얼 번호가 같으므로 `/dev/serial/by-id` 하나만으로 축을 구분하지 않습니다. 보드별 `Jn READY V2`로 식별합니다.
- 세 MCU의 ATmega328P 서명 `0x1e950f`를 확인했습니다. 기존 flash를 읽어 백업한 뒤 V2를 기록하고 avrdude의 기록 후 검증까지 통과했습니다.

처음 실물 종료 검사에서 pyserial의 POSIX `read()`와 다른 스레드의 `close()`가 겹치며 `fd=None` TypeError가 발생했습니다. 종료 순서를 STOP 송신 → 출력 버퍼 대기 → `cancel_read()` → 스레드 join → 포트 close로 수정했습니다. 수정 후 실물 종료 로그에서 Traceback/TypeError가 다시 발생하지 않았습니다.

배포 코드 기준은 종료 경합 수정 커밋 `dc8878f`입니다. 실제 재부팅 전에는 세 보드가 모두 V2로 연결됐습니다. 재부팅 후에는 `/dev/ttyUSB*`와 `lsusb`에서 세 FTDI 장치가 모두 보이지 않는 상태가 확인됐고, 사용자가 케이블은 연결되어 있지만 보드 전원은 꺼져 있다고 확인했습니다. 이때도 웹 서버와 데스크톱은 정상 기동했으며, 보드 전원을 켠 뒤 USB 자동 복구의 실물 검증은 별도로 남아 있습니다. 운영체제의 장치 미검출을 프로그램의 연결 성공으로 표시하거나 가정하지 않습니다.

## 재부팅 후 USB 전원 진단

- 사용자는 세 아두이노의 5V가 서로 연결되어 있으며, USB 하나를 분리 후 다시 연결해도 전원 LED가 켜지지 않는다고 확인했습니다. 비교할 다른 USB 기기는 없습니다.
- Pi는 Raspberry Pi 4 Model B Rev 1.5이며 VL805 펌웨어는 `000138c0`입니다. 부트로더/EEPROM 설정이나 펌웨어는 변경하지 않았습니다.
- `lsusb`에는 루트 허브와 내부 VIA 허브만 보입니다. FTDI 장치 및 `/dev/ttyUSB*`는 없습니다. `get_throttled=0x0`, 확인한 허브 포트의 과전류 카운터는 0이며 관련 커널 오류는 확인되지 않았습니다. 이 기록만으로 실제 VBUS 전압이나 하드웨어 정상 여부를 판정할 수는 없습니다.
- USB 런타임 절전 해제 확인 후 기존 설정을 복원했습니다. 이어 uhubctl 2.6.0으로 USB 전원을 2초간 한 번 순환했습니다. 강제 옵션은 사용하지 않았으며 USB2/USB3 허브의 모든 외부 포트가 power 상태로 돌아왔지만 보드는 다시 나타나지 않았습니다. 방법은 [uhubctl의 Pi 4 안내](https://github.com/mvp/uhubctl#raspberry-pi-4b)를 따랐습니다.
- 진단 후 서비스는 active/running, NRestarts=0이며 health 응답은 running 및 세 축 모두 미연결입니다. 모터 이동이나 원점 탐색 명령은 보내지 않았습니다.
- 포트 고장, 케이블, 공통 5V 회로 중 원인은 아직 특정하지 못했습니다. 전원을 완전히 차단한 상태에서의 배선 분리 점검, 단독 보드/케이블 시험 또는 전압 측정이 남아 있습니다. 추가 소프트웨어 전원 순환은 수행하지 않습니다.

## 기계 동작과 미해결 사항

- 사용자 확인: 현재 실제 모터는 1축만 장착되어 있습니다. 2·3축은 미장착입니다.
- J1에는 현재 좌표 기준 2° 및 5° 왕복 명령을 시험했습니다. 보드 카운터는 정상 완료했고 마지막 위치는 0으로 복귀했습니다. 5° 왕복의 카운터는 0→444→0입니다.
- 사용자는 처음 모터 선이 연결되지 않았고, 연결 후 재시험에서도 회전 없이 소리만 났다고 확인했습니다. 따라서 **실제 모터 회전 성공으로 판정하지 않습니다.**
- 사용자는 DM556과 모터 사이 배선 문제를 추정하며, 현재는 해결할 수 없어 소프트웨어 검증을 우선하도록 요청했습니다. 추가 기계 이동 시험은 중단했습니다.
- J2·J3은 실제 모터가 없으므로 명령 처리·스텝 카운터만 시험했습니다. 각 1° 이동 명령 및 복귀 완료 응답을 확인했습니다. 기계 회전은 검증하지 않았습니다.
- J1/J2 엔코더 유효값은 수신되지 않습니다. J3은 raw 값은 읽히지만 자석 약함 상태입니다. 배선·자석·센서 장착은 추가 점검 대상입니다.
- 원점 탐색은 수행하지 않았습니다. 엔코더와 센서의 물리 상태가 검증되기 전에 긴 탐색 이동을 하지 않습니다.

현재 통과 범위는 웹·서버·서비스 수명·USB 명령 및 펌웨어 스텝 카운터입니다. 배선 복구 뒤 실제 모터 회전, 방향·감속비, 엔코더 추종, 원점 센서와 정밀도는 별도 검증해야 합니다.
